# Project Plan

## Project Name

Break Free: A Wellness App

## Project Overview

Break Free is a wellness app concept designed to help teenagers and young adults take intentional breaks from their phones. The project will demonstrate the concept through a two-page website prototype.

The website will explain the purpose of the app, how it works, and the different activities users can complete.

## Work Breakdown Structure

### 1. Project Planning

* Define the purpose of Break Free.
* Identify the target audience.
* Define the main app features.
* Create the project scope.

### 2. Website Design

* Plan the homepage layout.
* Plan the About page layout.
* Choose a consistent visual style.
* Plan navigation between pages.

### 3. Website Development

* Create `index.html`.
* Create `about.html`.
* Create `style.css`.
* Connect both pages through navigation.
* Test the website in a browser.

### 4. Project Documentation

* Complete `scope.md`.
* Complete `plan.md`.
* Complete `retrospective.md`.
* Create `README.md`.

### 5. Testing and Deployment

* Check that all links work.
* Check that both pages display correctly.
* Check the website on different screen sizes.
* Publish the website using GitHub Pages.
* Prepare screenshots and project files for submission.

## TAME Risk Analysis

TAME stands for **Transfer, Accept, Mitigate, and Eliminate**. It provides a way to identify possible project risks and decide how to handle them.

### Risk 1: Project Takes Longer Than Expected

**Risk:** Building and documenting the website may take longer than planned.

**TAME Response: Mitigate**

I will break the project into smaller tasks and complete the website files before working on the remaining documentation.

### Risk 2: Website Links Do Not Work

**Risk:** The Home and About navigation links may not work correctly.

**TAME Response: Mitigate**

I will test each link before submitting the project and make sure the filenames match the links in the HTML.

### Risk 3: Website Design Does Not Display Correctly

**Risk:** The website may look different on different screen sizes.

**TAME Response: Mitigate**

I will use responsive CSS and test the website at different browser sizes before submission.

### Risk 4: Project Requirements Are Missing

**Risk:** A required document or file could accidentally be left out.

**TAME Response: Eliminate**

I will use the assignment requirements as a checklist and verify that every required file is included before submitting.

### Risk 5: GitHub Pages Does Not Publish Correctly

**Risk:** The website may not immediately appear after being published through GitHub Pages.

**TAME Response: Accept**

If a publishing issue occurs, I will troubleshoot the GitHub Pages settings and verify that the repository contains the required website files.

## Project Success

The project will be successful when the required files are completed, the two website pages function correctly, the documentation is included, and the website is successfully published through GitHub Pages.
